Security FINDING 9(b): the aggregate matched a check by name with
  awk '$1==n {print; exit}'
which takes the FIRST row the API happened to list. If two check-runs ever
share a name on one SHA — a re-run, or two workflows defining the same job
name — the gate read whichever came first, so a STALE SUCCESS could mask a
CURRENT FAILURE.

The row-selection rules now live in scripts/ci-required-select.sh, which
the workflow calls and which runs outside Actions, so this demonstration
drives the shipped code rather than a copy of it.

================= CASE 1: duplicates DISAGREE =================
rows ('test' has a stale SUCCESS at 18:00 and a newer FAILURE at 19:00):
  fmt^Icompleted^Isuccess^I2026-09-20T18:00:00Z
  test^Icompleted^Isuccess^I2026-09-20T18:00:00Z
  test^Icompleted^Ifailure^I2026-09-20T19:00:00Z
  vet^Icompleted^Isuccess^I2026-09-20T18:00:00Z

--- RED: the OLD selection, awk '$1==n {print; exit}' ---
  fmt: success  (started 2026-09-20T18:00:00Z)
  test: success  (started 2026-09-20T18:00:00Z)
  vet: success  (started 2026-09-20T18:00:00Z)
  => every required check reads 'success'; the gate goes GREEN on a failing lane.
